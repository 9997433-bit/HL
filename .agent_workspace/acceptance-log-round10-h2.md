# Round 10 · H2 验收片段：拍照识字精度基准补真实样张（10 张 → 13 张，九类版面）

> 分支：`cursor/r10-literacy-ocr-real-9f67`（基线 `cursor/openmoji-integration-9f67` @ `d89c455`）
> 探针：`npm run check:round10` → **H2 PASS**；`npm run check:round9` → **8/8 无退化**
> 复跑：`npm --prefix apps/literacy-app run test:ocr:accuracy`（约 1 秒，已挂在 `npm test` 上）
> 机读：同一命令加 `--json`，标记 `marker: "ROUND10_H2"`（`supersedes: "ROUND9_H2"`）

## 1. R9 满分下面藏着什么

R9 把基准集扩到十张、分了八类版面，跑出 55/55（100%）。这个成绩是真的，
但它有一个共同的出身问题：**十张全是浏览器渲染出来的**。字形是 WenQuanYi /
Droid Sans Fallback 画的，噪点是 `feTurbulence` 撒的，失焦是 `blur(2px)` 加的，
手写是 `JITTER` 表逐字抖出来的。

合成图守得住引擎侧退化——语言包换了、tesseract 升级了、预处理写反了，分数立刻掉。
但它守不住另一件事：**真实世界的字长什么样**。真实照片里的字有反光、有断笔、
有树影、有镜头畸变，还有印刷时就没印匀的边缘。十张合成图跑 100%，孩子举着手机
拍小区绿化带的告示牌可能一个字都对不上，这段差距在合成图上永远看不见。

ROUND10_H2 补的就是这一段：新增 `real-photo` tier，收三张**真人用手机拍的照片**。

**处理链**：`apps/literacy-app/scripts/gen-ocr-real-samples.mjs`（`npm run gen:ocr:real`）
从 Commons 取原图，只做三件事——按清单里写死的归一化裁剪框裁剪、等比缩放、存 PNG。
**不做灰度、不拉对比度、不去噪、不锐化**：那些是 `utils/ocr.js` 的 `preprocess()`
在运行时该干的活，烘进基准图就等于把被测对象和测试数据混在一起了。

**授权与可复现**：出处清单 `scripts/fixtures/ocr/real-samples.json` 记着原图 URL、
作者、许可证和 **sha256**——上游哪天换了文件，重画时当场报错，而不是悄悄换一张图
重定基准。裁剪属演绎作品，`real-*.png` 按与各自原图相同的 CC BY-SA 版本再分发，
署名写进 `THIRD_PARTY_NOTICES.md` 第三节。这三张只在测试里用，**不进 `public/`、
不打进 dist、不随两个 zip 发给孩子**（理由同 R9：离线包的额度不花在测试图上）。

删掉 `.cache/` 从零重跑一遍，三张 PNG 的 sha256 与入库版本逐字节一致。

门禁阈值（都在实测值下方留了余量）：
总召回 ≥ 90%；`real-photo` 这一类**单独**定 ≥ 75%（`REAL_TIER_RECALL`）；
单图召回下限 50%–100%，喷漆那张压到 50%，另两张 75%；
关键字（「花草」「小心」）一个都不许丢；误检 ≤ 2 字（复杂背景那张仍是 3）；
置信度下限 45 / 55 / 60（实测 70 / 78 / 86）。

## 4. 台阶在哪：同一句话，两种落地方式

最有说服力的一条不是平均分，是这两行摆在一起：

- 商场警示锥上的「小心地滑」是印刷体贴膜 → **4/4，置信度 86**；
- 水泥墙上的「小心地滑」是喷漆模板字 → **3/4，置信度 70，「滑」被读成「海」**。

模板字的笔画被镂空条断开，「滑」的三点水和月字旁在断口处糊到一起，引擎稳定地
给出「海」。换裁剪框、换输出宽度（200 / 260 / 320 / 400 / 500 / 640 / 800 px 全试过）
都只在「海 / 淤 / 湾 / 温」之间摆动，没有一档能认出「滑」。

这不是 bug，是当前离线 `chi_sim` 在断笔喷漆字上的**真实边界**。R9 的合成图不会
出现这种断口，所以它永远报 100%。现在这条边界被写进阈值了：谁改预处理、换语言包，
都得先跟 `3/4` 这个数对账；哪天真能认出「滑」了，回来把线抬上去。

## 5. 三条踩坑记录（都写进了脚本头注释）

**其一，边框会把整页吃掉。** 最早选的是一块「当心落物」金属标牌，字大、对比高、
看着比谁都好认，结果整页零召回，`data.text` 只剩 `[ED`——字外面那圈黑色矩形被
tesseract 当成了版面框。把裁剪框收进矩形内侧，同一张图立刻 **4/4、置信度 92**。
（这张最后没入库，因为「当」「落」不在本应用 1820 字的字表里。）

**其二，图不是越大越准。** 「爱护花草」在 320 px 宽时 4/4、置信度 90，放到 640 px
反而掉到 2/4（「党扩花草」）。tesseract 对字高有个舒适区，超出去反而糊。
清单里每张的 `width` 都是逐档实测挑的，不是随手写的。

**其三，选图先查字表。** 基准图上的字必须全在字库里（脚本里那条
`splitByLibrary(...).unknown.length === 0` 断言），否则「认出来却讲不了」。
候选里「当心落物」「地下消火栓」都因为缺字被刷掉——真实照片不能像合成图那样
想写什么字就写什么字，这是补真实样张比画一张图麻烦的地方。
两行牌子只取第一行也是同一个道理：「爱护花草／禁止踩踏」里的「禁止踩踏」四个字
不在字表内，留在画面里就会变成误检。

## 6. 断言覆盖

| 段 | 断言数 | 内容 |
|---|---:|---|
| 引擎跑分 | 16 | 逐图召回率 / 关键字 / 误检额度 / 置信度（13 项）+ 总召回率 + 基准集规模与 tier 覆盖 + **`real-photo` 张数与该类召回率** |
| 出处与授权 | 1 | 每张 `real-*.png` 都能在 `real-samples.json` 里查到 `page` / `file` / `author` / `license` / `licenseUrl` / `sha256`，裁剪框合法，清单里的字与基准集一致，且**出处链接与作者必须出现在 `THIRD_PARTY_NOTICES.md`** |
| 预处理 | 4 | 同 R9（缩放边界、灰阶拉满、近纯色不拉伸、空图报错） |
| 形近复核 | 4 | 同 R9（`buildListen` / `buildQuiz` 走形近池、干扰项来自形近库、退化路径、四个不重样的选项） |

合计 25 项（R9 是 20 项），实测 **25/25 通过**。

新增的两道锁：`MIN_REAL_IMAGES = 2` 管张数（`check:round10` H2 的门槛就是 ≥2 张），
`REAL_TIER_RECALL = 0.75` 管这一类自己的分数。真实照片最容易被「省事」掉——
要找授权、要核哈希、分数还不好看，换谁都想删两张换回合成图。这两条线拦着，
删了当场红灯，而不是让总召回率还在 90% 以上蒙混过去。
出处那条断言同理：CC BY-SA 的署名义务不靠自觉，漏一条测试就红。

## 8. 回归口径

- 换语言包、升 `tesseract.js`、改 `preprocess()`：先跑 `test:ocr:accuracy --json`，
  **逐 tier** 对第 3 节的表。合成八类必须仍是 100%（它们没有理由变），
  `real-photo` 不得低于 92%；真的提升了再把阈值往上抬。
- 换真实样张：先改 `real-samples.json`（含新的 sha256 与裁剪框），跑
  `npm run gen:ocr:real` 重画，把署名补进 `THIRD_PARTY_NOTICES.md`，
  最后回填本片段的实测表与脚本阈值。漏署名那步会被第 6 节「出处与授权」当场拦下。
- 删真实样张或砍 `real-photo` tier：`MIN_REAL_IMAGES` / `REQUIRED_TIERS` 当场红灯，
  `check:round10` H2 同步转红。
- 上游 Commons 改了原图：`gen:ocr:real` 的 sha256 校验会拒绝重画并打印新旧哈希。
  此时先核对新版本的授权，再决定是重定裁剪框还是换图，**不要直接把新哈希抄进清单**。
- 真机 WebView 实测（R10 简报里 L-M10 的另一半）归 `r10-perf-device-desktop-9f67`
  的设备清单，本片段只覆盖 Node 侧的引擎跑分。
