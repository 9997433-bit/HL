## 4. 音频 DSP 行业标准合规

### 4.1 响度:ITU-R BS.1770-5 + EBU R128

- **K 加权:** 两级预滤波(高架滤波 +4dB@高频 + RLB 高通),系数按 BS.1770 规范在任意采样率下重新推导(不得硬编码 48kHz 系数用于其他采样率)。
- **门限:** 积分响度采用 −70 LUFS 绝对门限 + 相对门限(−10 LU)双级 gating,400ms 块、75% 重叠。
- **量纲:** Momentary(400ms)/ Short-term(3s)/ Integrated(门限);LRA 按 EBU Tech 3342(短期响度分布 10%–95% 百分位,−20 LU 相对门限)。
- **True Peak:** ≥4× 过采样(48kHz 时;192kHz 可 2×)内插峰值检测,按 BS.1770 Annex 2。
- **合规验收(硬性):** EBU Tech 3341 "EBU Mode" 测试向量:
  - 响度用例(3341 cases 1–9 等):偏差 ≤ **±0.1 LU**;
  - True Peak 用例:偏差 **+0.2 / −0.4 dB** 容差内;
  - LRA 用例(Tech 3342):偏差 ≤ **±1 LU**。
  - 测试信号可由脚本按 Tech 3341/3342 规范合成(正弦/扫频/突发),纳入 CI。
- **响度归一化目标预设:** EBU R128(−23 LUFS/−1 dBTP)、流媒体常用(−14 LUFS/−1 dBTP)、广播美标 ATSC A/85(−24 LKFS/−2 dBTP);LUFS/LKFS 等价,UI 注明。

### 4.2 测量与文件交换:AES / EBU 规范

- **AES17-2020:** 数字音频设备测量方法 —— THD+N、动态范围、通带纹波的测量脚本按其加权与带宽约定实现,作为 §3.2 指标的测量依据。
- **AES5:** 首选采样率(44.1/48/88.2/96/176.4/192 kHz)全支持;非整数比 SRC(44.1↔48)为质量试金石。
- **BWF(EBU Tech 3285):** bext chunk(originator、time reference、coding history)读写保留;**RF64(EBU Tech 3306)** 支持 >4GB。
- **EBU Tech 3343:** 响度归一化生产实践指引,作为响度工作流 UI 文案与默认值依据。
- **dBFS 约定:** 满幅正弦 = 0 dBFS(AES17 约定),文档与 UI 标注一致。

### 4.3 采样率转换(SRC)质量目标

| 档位 | 通带纹波 | 阻带衰减 | THD+N(1kHz, 96k→44.1k) | 参照 |
|------|---------|---------|--------------------------|------|
| 最高质量(离线) | ≤ ±0.01 dB(0–20kHz) | ≥ 140 dB | < −130 dBFS | libsoxr VHQ / r8brain |
| 实时(varispeed/监听) | ≤ ±0.1 dB | ≥ 100 dB | < −100 dBFS | — |

- 验证:infinite-wave 式测试(扫频频谱图观察镜像/混叠、1kHz 音调 THD+N、脉冲响应相位)。自研 SRC 达不到阈值时,**必须**改用 libsoxr/r8brain 级第三方库——此项不接受"够用了"。

### 4.4 插件标准:VST3 / AU

- **VST3:** 使用 Steinberg VST3 SDK(GPLv3 或签署 Steinberg 专有协议双许可——项目开源许可证必须与所选路径兼容,见风险 R2);须通过 SDK 自带 `validator` 对宿主兼容性的基本要求:参数自动化、状态 chunk 保存/恢复、latency 上报消费(PDC)、旁链(可延后)。
- **AU(Audio Unit v2/v3):** macOS 使用系统 `AudioComponent` 枚举;`auval` 通过的第三方插件应能加载。
- **宿主验收:** 至少 3 款主流免费 VST3(如 TDR Nova、Voxengo SPAN、Valhalla Supermassive demo)在三平台(AU 在 mac)加载、处理、保存工程后状态完整恢复;PDC 用已知延迟插件做 null test 验证对齐。
- **CLAP/LV2:** 记为 P2,不纳入 Round 3 验收。

## 8. Round 2 / Round 3 优先攻坚项

### Round 2(靶向重构与深度优化)——按序
1. **验证基础设施先行(G10):** 3341/3342 测试向量合成器、AES17 测量脚本、golden-file 框架、三平台 CI 骨架。**理由:先有尺子,再谈达标。**
2. **实时引擎整改(G1/G8):** 对 Round 1 产出做回调纪律审计,重构为锁自由 + 异步流式 I/O;统一三平台后端抽象。
3. **计量合规冲刺(G3):** BS.1770-5 全链路过 3341 向量;响度归一化(M8)基于其上。
4. **SRC/抖动定级(G5):** 测量 Round 1 实现,不达标立即切换 libsoxr 级依赖。
5. **编辑核心加固(G2):** 分段引用式非破坏模型 + 100 步 undo + RF64 流式。
6. **EQ/动态精度整改(G6):** 扫频回归 + True Peak 限幅合规。

### Round 3(SOTA 打磨与最终验收)——按序

3. **UI 专业化与无障碍(G9/S7):** 60fps、停靠工作区、键盘闭环、AA 对比度、色盲安全。
