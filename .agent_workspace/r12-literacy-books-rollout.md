## 生成的书怎么加场景

`src/data/books/l*.js` 是 `scripts/gen-books.mjs` 生成的，手改会在下次
`npm run gen:books` 时被冲掉——所以扩充绘本的场景写在新增的
`scripts/data/book-scene-seed.mjs`，由生成器合进页对象。手写的 30 本
（`books/core.js`）不参与生成，场景直接写在书里，和 b1 同规格。

种子里的元素用元组，不用对象字面量：一页四五件东西，键名重复五遍全是噪声。

```js
{
  id: 'bx1',
  title: '水里的朋友',
  pages: [
    { bg: 'water', alt: '水里有鱼', s: [['🐟', 38, 62, 1.5, 'sway'], ['🌊', 22, 84, 1.3, 'drift']] },
    // …每页一项，不上场景的页写 null
  ]
}
```

`[图形, x, y, 大小?, 动效?]` 展开成 `{ e, x, y, s, m }`。

**为什么种子要写书名和逐页对齐**：`bx` 编号是按 `BOOK_SEED` 的下标算出来的，
在种子文件里插一本、挪一行，编号就整体后移，场景会安静地贴到别的句子上——
画面还是画得出来，只是「小鸟在雨里找不到家」配到了「桌上有米饭」那一页。
这种错没有任何报错，只能靠硬对齐挡：生成器同时核对 id 存在、书名一致、
页数逐页对齐，外加元素件数 2–6、背景预设存在、动效在白名单，
任何一条不满足就退出、不写文件。

## 校验

`check:data` 在 R11 四条之上新增三条，全绿：

```
✓ 页级场景样板 17 本 / 105 页（要求 ≥ 1 本且 ≥ 5 页）
✓ 场景铺开与 ROUND12_H3 台账一致：17/17 本、105/105 页      ← 新增
✓ 场景页 105 页（ROUND12_H3 门槛 ≥ 60）                    ← 新增
✓ 场景元素的坐标、大小、动效和背景预设都合法（一页最多 6 件）
✓ 场景旁白也只用了字表内的汉字
✓ 每个场景页都至少两件元素且留着兜底 emoji
✓ 全部 132 本每页都留着兜底 emoji                          ← 新增
```

台账 `ROUND12_H3 = { target: 60, books: 17, pages: 105 }` 写在
`src/data/books.js`，数字是手写的，不是从 `TOTAL_SCENE_PAGES` 算出来的——
算出来的数永远等于自己，挡不住任何事。写死一份让门禁拿它跟实际数据对：
谁把一本书的 `scene` 删了、谁的生成器跑歪少写一页，都会在这里炸出来，
而不是等到有人翻到那一页才发现插图退回了单 emoji。

最后一条覆盖全部 132 本（不只是升级过的 17 本）：书架和不支持场景的旧入口
都还在用 `emoji`，丢一页就空一格。

## 回归

`scripts/smoke.mjs` 新增 `ROUND12_H3` 一项交互。R11 那条验的是「一本样板画得对」，
铺开之后要防的是另一件事——数据里堆够了页数、渲染却没跟上。所以逐页比对三个数：

1. 数据里 `page.scene.length` 声明几件；
2. DOM 上 `data-scene-items` 声明几件；
3. `.scene__item` 真的画出来几件。

三个数对不齐就是渲染没兑现数据。同一趟还验：每页 `data-scene="dsl"`
（没有哪页悄悄退回单 emoji）、每件元素中心点落在舞台矩形内、
`aria-label` 与 `sceneAlt` 逐字相同。开头先核对台账与数据一致且 ≥60。

抽样 4 本而不是全量：17 本 105 页翻一遍要几分钟，冒烟没这个预算。
取首、尾和中间两本，手写的 `core` 和生成的 `l1` 都覆盖得到；
书是从数据里挑的，铺开范围再变，抽样跟着走。
