# Round 11 · H2 验收片段：OCR 实拍矩阵扩到 6 张 + 认不出时的降级话术

> 分支：`cursor/r11-literacy-ocr-matrix-9f67`（基线 `cursor/openmoji-integration-9f67` @ `4236625`）
> 探针：`npm run check:round11` → **H2 PASS**、**H8 PASS**（`check:round10` 8/8 无退化）
> 复跑：`npm --prefix apps/literacy-app run test:ocr:accuracy`（约 3 秒，已挂在 `npm test` 上）
> 机读：同一命令加 `--json`，标记 `marker: "ROUND11_H2"`，
> `supersedes: ["ROUND10_H2", "ROUND9_H2", "ROUND8_H4"]`

## 1. R10 的三张证明了什么，又漏了什么

R10 建了 `real-photo` tier，收三张真人拍的照片，跑出 11/12。这一步是对的——
它第一次让「真实世界的字」进了基准集，也第一次让台阶显了形（同一句「小心地滑」，
警示锥上的印刷体 4/4，墙上的喷漆模板字只有 3/4）。

但那三张有一个共同点：**都是白天户外的印刷标牌**。同一种光、同一种字、
同一种拍法。三张只够证明「真实照片认得出」，证不了「哪一类真实照片认不出」。
孩子真正会举起手机拍的东西比这宽得多——教室后墙的黑板、商场墙上的金属字、
家里那本翻旧了的绘本。

更要紧的是另一半：**这套引擎有相当一部分时候就是认不出来**。喷漆那张到今天
也只有 3/4，手写体和艺术字更是稳定失手。R10 交付时，界面在这半边只有一句
「这张照片里没认出字库里的字。把镜头凑近一点、让字更大更清楚，再拍一次试试」，
等于告诉孩子「是你拍得不好」——可有些照片他再拍十次也认不出来。

ROUND11_H2 补的就是这两段：**扩样到六张不同条件的实拍**，以及**把失败那半边
的话术也纳入基准的守备范围**。

全集：**16 张图 / 9 类版面，总召回 77/78（98.7%）**。
合成八类（印刷体 16/16、暖光 4/4、反色 4/4、失焦 11/11、手写 8/8、低光 4/4、

门禁阈值（都在实测值下方留了余量）：总召回 ≥ 90%；`real-photo` 单独 ≥ 75%；
新三张的单图下限 0.75 / 0.66 / 0.75，置信度下限 70 / 60 / 60（实测 93 / 84 / 76）；
关键字「小心」「手间」「中华」一个都不许丢。

## 4. 认不出的那一半：三条话术，一张卡，三个出口

`CameraOcrView.vue` 里新加的不是一句安慰，是三条**照着做就可能有用**的动作，
顺序按「改了最可能有用」排：

1. 💡 **换个亮一点的地方，别让手影或者灯的反光压在字上** —— 暗和反光是最常见的原因；
2. 🔍 **把镜头凑近，让那几个字占满大半个画面，端稳一秒再拍** —— 对应基准集里
   「图不是越大越准」那条踩坑的反面：字太小才是真的认不出；
3. ↩️ **还认不出就换一张：手写体、艺术字和褪色的招牌，它现在确实认不了** ——
   这条特意把边界说破。让孩子对着同一张手写照片反复重拍，才是真的耽误时间。

三种失败并到同一张降级卡（`data-trouble`）：

| `data-trouble` | 触发条件 | 卡上的第一句 |
|---|---|---|
| `blank` | 引擎跑完，一个字都没落进结果 | 这张照片里一个字都没认出来 |
| `shaky` | 认出字了，但 `confidence < 60` | 认出来了，但把握不大 |
| `error` | 引擎起不来 / 识字包缺失 | 这次没认成 |

`shaky` 这一档是新的：以前置信度只在页脚以「把握 xx 分」的形式出现，孩子不会
把它当回事，认错的字看起来和认对的字一模一样。现在低于 60 分会先说一声。

卡底下坐着两个出口——「再拍一张」直接开相机，「试一张示例」是留给
「是不是这台设备坏了」的自证路径，示例图认得出就说明引擎没问题，是照片的事。

`known` 为空但 `unknown` 不为空（认出字了、只是都不在字库）仍走原来那条
「暂时讲不了」的提示，没有和失败混在一起。

## 5. 断言覆盖（25 项 → 33 项）

| 段 | 断言数 | 内容 |
|---|---:|---|
| 引擎跑分 | 19 | 逐图召回率 / 关键字 / 误检额度 / 置信度（16 项）+ 总召回率 + 规模与 tier 覆盖 + `real-photo` 张数与该类召回率 |
| 出处与授权 | 3 | 逐张核对 `page` / `file` / `author` / `license` / `licenseUrl` / `sha256` 与裁剪框，署名必须出现在 `THIRD_PARTY_NOTICES.md`；**新增**「来自 ≥5 张不同原图」；**新增**「往轮机读标记还在」 |
| **失败话术** | **3** | **新增**：三条话术在不在（光线 / 取景 / 换一张，且说明了认不了哪一类）、三个失败分支与两个出口在不在、低置信度提醒线跟实测分数对不对得上 |
| 预处理 | 4 | 同 R10（缩放边界、灰阶拉满、近纯色不拉伸、空图报错） |
| 形近复核 | 4 | 同 R10 |

实测 **33/33 通过**。三道新锁：

- `MIN_REAL_IMAGES` 2 → **5**，`MIN_IMAGES` 12 → **15**；
- **`MIN_REAL_SOURCES = 5`**：张数这条线有个便宜的绕法——从同一张原图上裁五个位置，
  数字立刻够了，可光线、镜头、字体全是同一套。这条按清单里的 `page` 去重，
  堵的就是「一张图裁五刀」；
- **话术三项**：跑分再好看，话术被删掉也照样红。读的是源码而不是跑浏览器，
  一秒就能拦下；渲染出来长什么样由 `smoke.mjs` 那条拍照识字用例覆盖。

## 6. 三条踩坑记录（都写进了脚本注释）

**其一，改机读标记会误伤往轮门禁。** 把 JSON 输出里的 `supersedes` 从
`'ROUND9_H2'` 改成 `'ROUND10_H2'`，`check:round9` 的 H2 当场转红——分数一分没掉，
红的是一个字符串：那些探针读的是**去掉注释之后**的源码，头注释里的 `ROUND9_H2`
不算数。现在标记收进 `MARKER` / `SUPERSEDES` 常量并加了一条断言逐个核对，
下次谁再接替这个脚本，删掉哪一枚当场就知道。

**其二，选图仍然先查字表，而且比 R10 更难。** 候选里刷掉的：
「安全出口」（「出」不在 1820 字表内）、「注意安全」（「意」）、「儿童乐园」（「童」）、
「石排湾郊野公园歡迎您」（繁体 +「您」）。真实照片不能像合成图那样想写什么字写什么字。

**其三，美术字招牌是这套引擎的硬边界，不是调参能救的。**
武汉新华书店那块行书招牌（白字橙底、对比极高、人眼一秒认出）试了 320 / 480 / 640
三档宽度，**全部 0/4**，`data.text` 只剩 `-DRE`、`rnORE` 这样的碎片。
同一张黑板上抄的那首《望江南》也一样：「家在五湖东」只在 480 px 这**一档**上
凑齐 5/5，470 和 485 都掉回 2/5——这种刀尖上的分数不该写进基准，
所以最后取的是同一张图上稳定得多的粉笔落款（220–300 px 全档 4/4）。
这两条都进了第 4 节话术的第三句：手写体和艺术字，它现在确实认不了。

## 8. 回归口径

- 换语言包、升 `tesseract.js`、改 `preprocess()`：先跑 `--json` **逐 tier** 对第 3 节的表。
  合成八类必须仍是 100%，`real-photo` 不得低于 95.7%；真提升了再把阈值往上抬。
- 换真实样张：先改 `real-samples.json`（含新 sha256 与裁剪框），跑 `npm run gen:ocr:real`
  重画，署名补进 `THIRD_PARTY_NOTICES.md`，最后回填本片段的实测表与脚本阈值。
- 删样张 / 砍 tier / 从同一张原图凑数：`MIN_REAL_IMAGES`、`REQUIRED_TIERS`、
  `MIN_REAL_SOURCES` 三条分别当场红灯，`check:round11` H2 同步转红。
- 动 `CameraOcrView` 的失败分支或话术：第 5 节那三项断言会拦下。
  改 `SHAKY_CONFIDENCE` 也要跟真实样张的置信度下限对账——设得比最低那张还低
  等于从不提醒，设得比最高那张还高会把认对的也标成可疑，两头都会红。
- 真机 WebView 上的实际观感（尤其降级卡在小屏上的换行）归设备清单，
  本片段只覆盖 Node 侧的引擎跑分与源码契约。
