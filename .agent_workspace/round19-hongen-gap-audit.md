## 4. 审计发现（实现岗务必先读）

- **A. 580 不是「大概剩一半」**：R17 末模板 880（u56 起）；R18 消化 u56–u70 共 300，余 **u71–u99 = 580**。用户口头「880」是旧口径，本轮门禁以 **1820 全库富脚本**为准。正确姿势仍是扩 `char-play-seed.txt` → `npm run gen:play:rich`（分片落 `play-rich/uN.js`），禁止手改生成物正文。
- **B. H2 与 H3 文件族耦合但职责拆开**：H2 主攻 seed/生成物/分片数量；H3 主攻 `CharPlayStage` UI。冲突时 **Stage 以 H3 为准、数据以 H2 为准**。H2 扩到 1820 后分片会到 u99，H3 不得假设「只有 70 片」。
- **C. 「视频级」≠ 每题一个 MP4**：简报明确程序化讲解播放器（GSAP/CSS 时间轴 + TTS）。H4 最小闭环：自动按步推进 + 播放/暂停 + 进度；吃手写 `explain` 步文案；`prefers-reduced-motion` / 家长「减少动态」下降级为现有手动点步。不要为过针塞假视频文件。
- **D. H4 与 H5 串行友好、可部分并行**：播放器可先接 `buildAnalysis().steps`（手写优先、公式兜底）；H5 把 85→150 时必须保持 steps 与 `buildAnalysis` 步数对齐（R18 100% 红线，扩写不得打穿）。判题前不泄答案、语义模板不用具体名词——旧约束继续生效。
- **E. 精美度三件套要「可感知」**：探针会要可执行 `ROUND19_H3` + 至少三类信号（多拍节 timeline / 道具命中反馈增强 / 主题氛围层）。现有 `feedback.correct` 微缩放与 catch 下落**不够**凑三类升级——必须在 Stage 上能让走查截出「不像 R18」的差别。
- **F. 证据与门禁必须本轮落盘**：`evidence/r19/walkthrough.md` + ≥4 真图（全库富玩抽查 / 精美舞台 / 剖析播放器 / 周报或学伴）；H7 不得复用 r18 报告冒充。H8 在干净环境先 `npm run android:sim` 再宣称 round18 8/8。
