# 全面超越洪恩 · 主计划（Master Plan）

> 目标：**在功能模块、内容体量、性能与无障碍上全面超过「洪恩识字」「洪恩数学」**，
> 同时保持开源、零墙、离线、可导出等已有差异化优势。
> 验收口径：`.agent_workspace/sota-acceptance-criteria.md` **全部 P0/P1 清零** +
> 下文「洪恩模块对标表」**全部 ✅**。

---

## 0. 「全面超越」的判定标准

必须同时满足三层，缺一不可：

| 层级 | 含义 | 判定 |
|---|---|---|
| **A. 工程 SOTA** | 双 App 全部 P0/P1 验收项实测通过 | `npm run test:round3` + Lighthouse Perf/A11y ≥95 + acceptance-log 无 ❌ |
| **B. 洪恩模块对标** | 洪恩每个公开模块/能力都有对等或更强实现 | 见 §2、§3 对标表全部 ✅ |
| **C. 差异化反超** | 洪恩做不到或不愿做的能力必须领先 | §4 七项全部 ✅ 且可演示 |

**当前快照（2026-08-26，含 Round 3 在途合并）**

| App | 工程 SOTA (P0) | 模块对标 | 内容体量 vs 洪恩 |
|---|---|---|---|
| 识字 | ~70%（200字/5绘本/20成语/FSRS/a11y 已大幅推进） | 7/12 模块有 MVP，4 模块缺洪恩级深度 | **~11% 字库 / ~4% 绘本** |
| 数学 | ~57%（家长中心/数独三档/QuizShell 已有） | 7 星球有玩法，缺错题本/自适应/演示 | **母题 ~18% / 缺自适应闭环** |

结论：**方向正确，距离「全面超越」仍需 Round 4–7 四轮攻坚（每轮 10 子代理并发）。**

## 1. 执行模型

- **每轮 10 子代理**：fable×3（架构/审计/验收）+ opus-fast×4（功能落地）+ gpt-sol×3（脚本/性能/探针）
- **每轮结束门禁**：`npm run test:round3` 全绿 → `build:all` → 更新 `acceptance-log` → PR 合并 `cursor/hongen-edu-apps-9f67`
- **分支策略**：功能分支 `cursor/<topic>-9f67`，集成分支 `cursor/hongen-edu-apps-9f67`
- **内容策略**：数据驱动 JSON/JS；字库/绘本/母题用脚本批量生成 + 人工抽检，不手敲 1800 字

## 5. 分轮交付计划

### Round 4 · 「P0 清零 + 核心闭环」（下一批 10 子代理）

**识字**
- 单字学习状态机（认→写→听→测→奖）自动衔接
- 错 3 笔自动示范；徽章体系 v1
- 字库 **200→500**；characters.js 懒加载（Perf 冲 ≥90）
- 家长自定义学习计划（自选单元/每日新字数）

**数学**
- `wrongBook` 错题本 + 重练入口
- `adaptive.js` 调度器（连对升/连错降/弱项优先）
- PRNG 种子化 + 题目 ID；题库门禁 ≥300
- 日冒险 5 题 + 当前关高亮
- 比较模块 / 乘法入门入口

**共同**
- Lighthouse A11y/Perf 终测 ≥95（gzip 静态服、首屏拆包）
- `check:tokens` Phase 2/3 完成
- acceptance-log-round3 回填 + zip 重打

**门禁**：P0 总体 ≥95%；npm test 全绿。

## 7. 风险与原则

1. **内容不能靠手搓**：字库/绘本/母题必须脚本化生成 + CI 校验（`check:data` 扩展）。
2. **不复制洪恩 IP/美术**：用 OpenMoji + 程序化动画达到「好看够用」，不侵权。
3. **功能深度 > 功能数量**：每轮合并必须 test 全绿，禁止堆半成品路由。
4. **测量驱动**：Brief 里的数字必须 `acceptance-log` 实测，禁止写进简报不跑脚本。
