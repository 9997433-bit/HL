## 先说结论：这一包拍的是 R18 功能**合入前**的样子

走查当天 `cursor/r18-orchestration-9f67` 上只合进了简报、差距审计、smoke 探针和
往轮门禁；本轮四张主牌——**富 Play ≥1200**（H2）、**rich 按单元懒加载拆包**（H3）、
**剖析步数对齐 ≥90%**（H4）、**精品剖析 ≥80**（H5）——一条都还没有代码落地
（`cursor/r18-play-rich-1200-9f67` 等分支当时还停在基线 `770bded`）。

所以这一包的定位是**基线实拍 + 当场实测的缺口台账**：四类场景全都是真页面、
真数据，但富玩数、拆包体积、步数一致率记的都是合入前的读数。
**R18 功能合入后必须用同一条命令复测**，用同一套 `data-*` 契约和同一张实测表比对；
在那之前，任何人拿这一包声称 R18 达标都是错的。

## 这份东西是怎么产生的

`npm run build` 出两个 App 的 dist，脚本给它们各挂一台本地静态服务，再用真
Chrome（148.0.7778.96 / Node v22.14.0，headless）**从入口一路点进去**，
到值得看的画面就落一张 PNG。不是对着组件单独渲染，也不是把设计稿导出来。

其中两张不是页面截图，是**实测面板**：

- `r18-04` 的表格来自 CDP 的 `Network.responseReceived` / `Network.loadingFinished`
  事件，禁缓存冷开一次单字详情，逐个分片记 `encodedDataLength`；
- `r18-06` 的表格来自本进程直接 `import` 了 `wordProblems.js` 和 `wpAnalysis.js`，
  把 214 道母题各实例化一次、跑一遍 `buildAnalysis`，再和 `template.steps` 比。

两张表里的每个数字都是这一次运行量出来的，渲染成表格再拍照，没有手搓的图。

家长周报那张**故意排在最后**：剖析那一幕答的 8 道题会真的落进本机存档，
周报读的就是那一份，所以卡上「做了 8 道题」是走查自己攒出来的；
也因此数学侧全程共用一个浏览器上下文，中途不清 localStorage。

## 四类场景

### ① 富玩：手写富脚本的玩关，和还没轮到的那批字

走法：脚本先 `import` 一遍 `char-index` 与 `char-play`，按 `hasRichPlay()` 把字表
切成两拨，各取一个字直接进 `/#/learn/<字>`，清存档重载，从步骤条点到第 1 步「玩一玩」。

![富玩：手写富脚本的玩关](r18-01-play-rich.png)

第 40 单元之后取到的「各」：`data-play-template=sort-buckets`、
**`data-fallback=false`**（这一位是脚本的硬断言，取到回填关会直接报错退出），
旁白「各归各位：红的一边，蓝的一边。」——苹果 / 冰块 / 蓝莓 / 玫瑰要按颜色拖进两个筐，
玩法本身就在讲「各」的字义，不是套一个通用找茬。

![富玩缺口：还吃模板回填的字](r18-02-play-template-gap.png)

对照组「科」：**`data-fallback=true`**、模板 `emoji-hunt`，旁白
「一门一门的学问。图里有一个是『科』，把它找出来。」画面上是显微镜 + 加号 + 箭头 + 对勾，
干扰项跟「科」没有语义关系，孩子靠排除法就能中——这就是简报里说的「中后段手感断崖」。

走查当时的实测覆盖：**富脚本 940 条 / 字表 1820 字，旁白去重 940 句**（口径
`countRichPlays()` / `richPlayCoverage()`，探针标记还是 `ROUND17_H2`）。
距 R18 H2 的 ≥1200 还差 260 条，这张缺口图会在 H2 合入后变成手写关——复测时
先看「科」这一格是不是翻了。

### ② 拆包：单字关键路径现在到底吞了多少

走法：新开一个禁用缓存的页面，挂上 CDP 网络监听，冷开 `/#/learn/一`，
等页面 idle 后回到顶部拍首屏，再把这次真正下载的 JS 分片列成表。

![单字详情冷开首屏](r18-03-char-detail-single-char.png)

首屏就是孩子每天点最多的那一页：步骤条 🎮玩 → 👀认 → 👂练 → ✍️写 → 🗣️说，
第 1 步「玩一玩」直接展开，下面接「这个字的来历」。

![单字关键路径的实测分片表](r18-04-bundle-network.png)

实测：**16 个 JS 分片、合计 861.3 KB 传输字节**，其中

| 分片 | 传输字节 |
| --- | --- |
| `CharDetailView-*.js` | 406,836（397.3 KB） |
| `index-*.js`（应用主包） | 332,635（324.8 KB） |
| `index-*.js`（次包） | 70,660 |
| `distractors-*.js` | 39,214 |

`CharDetailView` 一个人就占了单字路径的 46%，因为它把 `char-play-rich` 整包同步
吃了进来（`char-play.js` 顶上 `import * as richModule`，不分单元）。这正是 H3 说的
「不再整包同步进单字关键路径」。H3 的按单元懒加载合入后复跑这一幕，这张表里
`CharDetailView` 应该显著变小，并且多出「切到哪个单元才拉哪一片」的分片——
表是同一张表，一比就知道拆没拆干净。

### ③ 剖析：面板长这样，步数对不对得上是另一回事

走法：进 `/#/word-problems`，点题面上的「🔍 剖析」，试着点「全部摊开」，
再点「看一道同结构的变式」。

![应用题剖析面板](r18-05-wp-analysis.png)

这一轮抽到的是「24 张明信片平均分给 4 个小朋友」：① 图示理解把 4 份条形画出来、
问句和「要求的」那一段用虚线框住；② 分步提示先讲「平均分要求每人一样多」，
再列 `24 ÷ 4 = ?`，**末步得数按设计盖着**（面板自己写了「算出来再回去选答案」）；
③ 变式换成 `4 ÷ 2 = 2`，结构一样只换数。右上角「跳过 ✕」全程在，
看完剖析接着答了 8 题，答题链路没被面板卡住。

![步数对齐实测](r18-06-wp-steps-audit.png)

但把 214 道母题全跑一遍：**`template.steps` 与 `buildAnalysis().steps.length`
只有 158 道对得上，一致率 73.8%**，离 H4 的 ≥90% 差 35 道；**剖析只有 1 步的有 104 道**。
不一致里最扎眼的是一整排 `sum-times-*`（声明 3 步、实际拆出 2 步）和
`div-remainder`（声明 2 步、只拆出 1 步）。孩子那边看到的是「标着三步题、
剖析只讲两句」，星数和 XP 却按 3 步算——这就是 H4 要修的东西。
这张表也是 H4 的验收底片：改完复跑，一致率那一行应当 ≥90%。

### ④ 周报与学伴

![数学家长周报](r18-07-math-parent-weekly.png)

进 `/#/parent`，读题面上的口算门算出答案过门。`data-weakness="thin"`：
「这周来了 1 天 · 共 0 分钟 · **做了 8 道题** · 弱项判定：来的天数太少」——
这 8 道就是第 ③ 幕答的那 8 道，周报读的是真存档。下面三条建议各自可点，
卡底印着「这段话是按本机存档现算的：没有联网，也没有拿别的孩子做对比」。

![识字学伴](r18-08-literacy-mascot.png)

识字首页点一下学伴，气泡说「复习不是重学一遍，是把快忘的字捞回来。」
这句会随进度换（同一天的另一次运行说的是「有 2 个老朋友在等你，先去打个招呼吧」），
说明台词是按存档挑的，不是写死的一句。

## 走查里发现的问题

**1. 模板回填关的干扰项不认字义。** 「科」那一关（`emoji-hunt`）给的是
显微镜 / 加号 / 箭头 / 对勾，只有显微镜跟「科」沾边，另外三个纯凑数。
题面写「图里有一个是『科』」，但图里没有任何一个是「科」字，说的是「代表科的图」。
这不影响通关，但和手写关比，孩子学不到字义。属于 H2 要翻的那 880 字的典型样本。

**2. 剖析步数不一致集中在两族题上。** 12 条不一致样本里 10 条是
`sum-times-*`（先求和再乘：声明 3、实际 2），另有 `div-remainder` 与
`average` 各走反方向（前者 2→1，后者 2→3）。也就是说这不是散点噪声，
修 `analyzeEquation` 的和差倍族与余数族大概率能一次收掉大半。

**3. 单场走查判不出 `thin` 以外的周报分支。** 弱项规则里 `thin` 的条件是
「活跃 ≤2 天且 <25 分钟」，优先级排在错题欠账、正确率偏低之前；一场走查只落在一天里，
所以无论答多少题、错多少题，周报必然判 `thin`。这张图能证明的是「周报读的是真存档、
数字对得上、建议可点」，**不能**证明其它分支的文案——那几条由
`npm run test:mascot` 用构造存档覆盖，不在本包里。

**4. 周报的「共 0 分钟」。** 8 道题答下来时长仍记 0 分钟，说明时长统计的粒度
（或起止口径）在这种短会话里会归零。没往下追，记在这里备查。

## 边界（这份包不能证明什么）

- **不能证明 R18 达标。** 上面每一处「合入后复测」都不是客套：富玩记的是 940、
  拆包记的是 861 KB、步数一致率记的是 73.8%，这三个数都还在门槛线下面，
  是**本轮起点**的读数。
- 全程 headless Chrome + 本地 dist，**不是真机**。Android 侧归 H7 管，与本包无关。
- 无音频：跑的时候带了 `--mute-audio`，跟读、旁白配音、音效都没有验证。
- 每张图都是**这一次**运行的产物。应用题抽哪道、学伴说哪句跟当时的存档和随机题序
  有关，重跑会换一道题；但走的路径、读的 `data-*` 契约和两张实测表的口径是固定的。
- 脚本日志里的「答了 8 题」是点击轮次，要看 App 真正记下的数就看周报卡（这一轮
  两边正好都是 8）。

## 复现

```bash
npm run build                       # 出两个 App 的 dist
npm run walkthrough:shots:r18       # 落 8 张 PNG + walkthrough-shots.json 到 evidence/r18/
npm run walkthrough:shots:r18 -- play-rich wp-steps   # 只跑其中几幕
```

需要本机有 Chrome/Chromium（脚本按 `CHROME_PATH` → `/usr/local/bin/google-chrome`
→ `/usr/bin/chromium` 的顺序找）。任何一幕的契约断言没过（比如富玩那一幕取到了
回填关），脚本会记进 `failures` 并非零退出，不会留下一份「看着挺全」的假证据。
