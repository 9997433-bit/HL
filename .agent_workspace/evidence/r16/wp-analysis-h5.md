## 分步为什么是解析出来的，不是逐题写的

母题库是「语义模板 18 × 场景皮肤 10 + 手写 34」笛卡尔积扩出来的 214 个母题，
每个母题每次 `make()` 数值都不同。逐题手写解析脚本扩不动，也一定会跟母题库
走散，所以分步由 `analyzeEquation()` 解析 `equation` 字符串得到：

- 词法只认 `0-9`、`+ − × ÷`、中英文括号、逗号分句、`……` 余数
- 递归下降边算边记，括号里的自然先记成一步
- 认不出的写法一律返回空步骤，面板退回显示整条算式，**不猜**

判题前答案所在那一步显示 `?`（有余数的除法按「问的是商还是余数」分别盖），
判完题才摊开——剖析不扣星，露答案等于绕开提示的星星代价。

## 可跳过与按需加载

面板不跟着路由打包。玩法页只留一个入口按钮，点开才 `import()` 面板与解析器：

| 构建 | `/` 首屏 | `/word-problems` 首次进入 |
|---|---|---|
| 未加剖析（基线 088c2cc） | 88.9 KiB / 96 | 35.5 KiB / 40 |
| 剖析随路由打包 | 88.9 KiB / 96 | **39.9 KiB / 40（余量 0.1）** |
| 剖析点开才下载（本分支） | 89.7 KiB / 96 | 36.1 KiB / 40（余量 3.9） |

首屏那 0.8 KiB 是 Vue 异步组件运行时（数学 App 头一次用 `defineAsyncComponent`）。
懒加载块照样进 `sw.js` 预缓存清单，离线也点得开。
面板只有一处 CSS 宽度过渡，`main.css` 的 `prefers-reduced-motion` 全局兜底（G4）。
