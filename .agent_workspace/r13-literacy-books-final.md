## 为什么按分级铺，而不是挑页数最多的书

R12 铺的是「读得最多的那一摞」，量到了但分级是断的：L1 的 `bx11`–`bx20`
没有场景，同一级里前十本有插图后十本没有。孩子不会按 id 翻书，他按书架顺序
翻——翻到第 11 本突然退回单 emoji，看起来就是「后面的书坏了」。

所以这一轮的分界线是**整级铺满**：先把 L1 补齐到 25/25，再往 L2 推。凑页数
的话挑 L4–L6 的长书更省事（一本 10–14 页），但那样 L1 会一直缺着，而 L1 正是
最需要图的那一级——那批孩子还读不动整句。

## 台账与守门

`books.js` 里现在有两份台账：

- `ROUND12_H3`（`target 60 / 17 本 / 105 页`）**原样留着**。它记的是铺开那一轮
  铺到了哪儿，改掉就没人知道 105 是从哪来的。
- `ROUND13_H3`（`target 200 / 33 本 / 209 页`）是当期台账。

`check:data` 三条：等值对当期台账、`≥ target`、**`≥` R12 台账**。第三条是防退化
——场景只能往上加，退回 105 页说明有人的改动把书吃回了单 emoji。数字写死而不是
从数据算，算出来的数永远等于自己，挡不住任何事。

smoke 那条抽样口径也改了。R12 按下标取首、尾和三分位共 4 本，铺到三个分级之后
这个取法会**整级漏掉 L2 的扩充绘本**（`bx21`–`bx26` 正好落在两个采样点之间）。
改成每级取头尾：`b1`(L1) / `bx20`(L1) / `b10`(L2) / `bx26`(L2) / `b14`(L3)，
5 本 33 页，手写 core、生成 l1/l2 和每级边界都覆盖到，仍在冒烟的时间预算内。

## 内容口径

- 每页 3–6 件元素（DSL 上限 6），没有 2 件的页——2 件是校验下限，不是编排目标。
- 背景预设分布：`room` 69 / `field` 66 / `sky` 25 / `water` 24 / `dawn` 7 /
  `dusk` 6 / `night` 6 / `snow` 3 / `storm` 3。L2 的叙事书按情节换背景
  （`bx23` 小狗过桥那本从 `field` 走到 `water` 再回 `field`）。
- 旁白直接从该页正文收敛，不引入正文以外的字：越界风险归零，读屏念出来的
  也和孩子看到的句子对得上。
- 图形位不放汉字（`verifyScenes()` 硬拦）。方向课那本（`bx13`）用
  `⬆️⬇️⬅️➡️` 而不是写「上下左右」四个字——那四个字要孩子从正文里读。
