# Round 11 H1 · 跟读离线 ASR 儿童评测集（骨架 36 条 → 目标 300 条）

> 数据：`apps/literacy-app/scripts/data/asr-eval-set.json`
> 跑道：`apps/literacy-app/scripts/test-asr-eval-set.mjs`（`npm --prefix apps/literacy-app run test:asr:evalset`）
> 判定：`.agent_workspace/r11-followread-gonogo.md`
> 来源口径：`.agent_workspace/r9-followread-asr-evaluation.md` §5
>
> 一句话：**不能用成人公开榜单代替儿童跟读验收**，所以这套集合必须自己录。
> 录之前先把骨架、字段、隔离规则和聚合器定下来——否则录完才发现分不出组，等于白录。

## 1. 为什么先有骨架，后有音频

模型没到、录音没录，先写 36 条占位看起来像在做表面功夫。但顺序反过来的代价更大：

- **分组要在录之前定。** 安静/噪声要分开算，年龄、性别、设备、口音要能切子组。
  等录完 300 条再发现「远讲全是同一个孩子」，说话人隔离就补不回来了。
- **聚合器要在数据之前跑通。** 漏字检出、静音误判这些指标的算法本身会错。
  占位阶段用模拟转写把它们跑一遍，错在代码里就当场暴露，而不是混在模型的错里。
- **隐私边界要在录之前立。** 音频一旦进了 git 历史就删不掉。占位阶段的硬约束是
  `audio` 恒为 `null`，harness 直接断言——没有例外通道。

## 3. 字段约定

```jsonc
{
  "id": "C001",            // 稳定 id，扩样只往后加
  "speaker": "S01",        // 指向 speakers[]；年龄/性别/口音/split 都挂在说话人上
  "env": "quiet",          // quiet | tv | far
  "device": "phone",       // phone | tablet
  "poem": "jingyesi",      // POEM_MAP 里的诗 id
  "line": 0,               // 第几句；原文由 poems.js 提供，评测集不复制正文
  "seconds": 4.2,          // 3–10 秒
  "category": "normal",    // 见上表
  "spoken": "床前明月光",   // 孩子实际读出的内容（占位阶段是设计意图）
  "mock": "床前明月光",     // 模拟转写，只在占位阶段存在
  "status": "placeholder", // placeholder | recorded
  "audio": null            // 占位阶段必须为 null
}
```

`split` 只写在 `speakers[]` 上，clip 不重复声明——这样「同一个孩子同时出现在 dev 和 final」
在结构上就写不出来。harness 仍然会再验一遍，因为将来可能有人把 split 挪到 clip 上。

## 4. 从占位到真数据

一条片段的生命周期：

1. **录制**：家长书面同意（可撤回、写明保存期限）→ 录音存到仓库外的受控目录 →
   去标识化编号（孩子只以 `S01` 这样的编号出现，不留姓名、学校、地区细粒度信息）。
2. **双标注**：两名普通话标注者独立写下「孩子实际读出的字」，分歧交第三人仲裁：

   ```jsonc
   "status": "recorded",
   "audio": "asr-eval/2026-09/C001.wav",   // 仓库外的相对路径
   "labels": { "a": "床前明月光", "b": "床前明月广", "arbiter": "床前明月光" },
   "spoken": "床前明月光"                   // 取仲裁结果
   ```

3. **删掉 `mock`**：harness 断言 `recorded` 的条目不许再留模拟转写——
   否则真假指标会混在一张表里，这是最容易骗到自己的地方。
4. **跑分**：`test-asr-eval-set.mjs` 把引擎输出喂给同一个聚合器，
   Go/No-Go 表的「实测」列开始有数。

## 5. 扩到 300 条的配额

按 R9 §5 的口径，300 条建议这样摊（现有 36 条是每一格至少落一条的最小骨架）：

| 维度 | 配额 |
|---|---|
| 年龄 | 4–6 岁 150 · 7–9 岁 150 |
| 性别 | 各 ~150，任一格不低于 120 |
| 环境 | 安静 150 · 电视背景 90 · 远讲 60 |
| 设备 | 手机 200 · 平板 100 |
| 异常 | 正常 150 · 漏字 45 · 多读 20 · 重复 15 · 静音 25 · 旁人说话 15 · 声调错 20 · 声母错 10 |
| 划分 | dev 120 · threshold 90 · final 90，说话人不跨集，每集不少于 8 个孩子 |
| 说话人 | ≥ 40 人，单人不超过 12 条（避免某个孩子的口音主导分数） |

扩样时只加 `clips[]` 和 `speakers[]`，不要动 harness 的覆盖下限——那些下限是
「不许缩回去」的地板，不是目标。

## 6. harness 现在守住的 11 条（占位阶段就生效）

1. 条数 ≥ 30、目标 300、id 不重复；
2. 每条对得上一句真实诗句、一个登记过的说话人；
3. 时长落在 3–10 秒；
4. dev / threshold / final 说话人零重叠，每集 ≥3 人 ≥6 条；
5. 每个划分都要有静音或旁人说话的负样本；
6. 两个年龄段、三种环境、两种设备、八类异常一个都不少；
7. 说话人性别 ≥2 种（否则子组差距无从算起）；
8. 占位条目 `audio` 必须为 `null`，`recorded` 条目必须有仓库外路径 + 双标注 + 仲裁；
9. `recorded` 条目不许残留 `mock`；
10. 异常样本名副其实：漏字真的短了、多读真的长了、静音真的没出声、发音错的字数和原文一致；
11. 同意策略、保存期限、去标识化三项声明齐全。

## 7. 已知局限

- 36 条占位撑不起任何统计结论，它只撑得起「管线跑得通」。
- 模拟转写是我们写的，它对模型的真实错误模式（尤其儿童共发音、拖音、气声）没有代表性。
- 声调/声母两类只各有 2 条，是给诊断层留的接口，不是诊断层的验收样本；
  诊断层要单独按 §5 的配额扩到 30 条以上才谈得上精确率。
- 录音的伦理与合规流程（同意书模板、撤回通道、删除时限）还没有落成文档，
  这是 F4 真正的长尾，比录音本身更花时间。
